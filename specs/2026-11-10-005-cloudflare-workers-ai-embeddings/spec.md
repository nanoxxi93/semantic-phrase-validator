# 005-cloudflare-workers-ai-embeddings: Integración de Cloudflare Workers AI (BGE-M3) para Embeddings Gratuitos

## Resumen
Permite al sistema utilizar Cloudflare Workers AI con el modelo multilingüe BGE-M3 (`@cf/baai/bge-m3`) como proveedor de embeddings alternativo de capa gratuita frente al servicio de inferencia de Hugging Face. La funcionalidad introduce una arquitectura multi-proveedor desacoplada mediante variables de entorno, soporta vectores densos de 1024 dimensiones, generaliza la función de similitud coseno matemática para admitir dimensiones dinámicas homogéneas, aísla estrictamente el catálogo y las comparaciones mediante una columna discriminadora de modelo en la base de datos, y provee herramientas de diagnóstico CLI y pruebas aisladas con cero coste de red. Asimismo, incorpora en la interfaz de usuario soporte dinámico y reactivo para ambos modelos: detección del modelo activo del servidor vía endpoint informativo, selector interactivo de los 2 modelos soportados que sincroniza de forma unificada la validación semántica, la creación de frases y la consulta del catálogo con el modelo seleccionado por el usuario, validación estricta en el backend que restringe el modelo a los 2 permitidos, badges visuales por frase indicando el modelo y dimensiones, y badges informativos en las tarjetas de validación y alerta de duplicados.

## Casos de usuario
- **CU-1**: Como operador o desarrollador del sistema, quiero seleccionar el proveedor de embeddings mediante la variable de entorno `EMBEDDING_PROVIDER` (`"cloudflare"` o `"huggingface"`), de modo que pueda alternar fácilmente entre la capa gratuita de Cloudflare Workers AI y Hugging Face sin modificar código fuente.
- **CU-2**: Como motor de validación semántica, quiero enviar textos cortos a la API REST de Cloudflare Workers AI para el modelo `@cf/baai/bge-m3` y recibir un vector plano de 1024 números de coma flotante que represente con alta fidelidad el significado semántico multilingüe de la oración.
- **CU-3**: Como motor de cálculo matemático, quiero que el cálculo de similitud coseno admita vectores numéricos de cualquier dimensión compartida (tanto 384 como 1024 dimensiones), garantizando determinismo, acotamiento numérico en `[0.0000, 1.0000]` y redondeo a 4 decimales.
- **CU-4**: Como usuario y administrador, quiero que tanto el proceso de validación semántica como la consulta de frases guardadas operen exclusivamente sobre el universo del modelo seleccionado o activo, evitando comparar o mostrar frases de otros modelos incompatibles para no generar confusión visual o matemática.
- **CU-5**: Como desarrollador, quiero disponer de un script CLI ejecutable (`npm run test:cf`) que pruebe directamente la integración con Cloudflare Workers AI evaluando tres oraciones canónicas (idéntica, paráfrasis y no relacionada), reportando métricas de similitud, latencia y recomendando la calibración óptima del umbral para BGE-M3 sin necesidad de arrancar el servidor web ni la base de datos.
- **CU-6**: Como suite de pruebas automatizadas, quiero poder simular el proveedor a 1024 dimensiones para verificar el flujo de validación y persistencia de Cloudflare de forma 100% determinista, aislada y sin llamadas de red.
- **CU-7**: Como usuario en la interfaz web, quiero visualizar dinámicamente en el encabezado qué modelo está activo en el backend y su umbral de corte real configurado, eliminando textos estáticos o porcentajes fijos desactualizados.
- **CU-8**: Como usuario en la interfaz web, quiero tener un selector con los 2 modelos soportados (Cloudflare BGE-M3 y Hugging Face MiniLM-L12-v2), para alternar dinámicamente el modelo con el que se validan semánticamente nuevas oraciones, se persisten y se visualiza el catálogo.
- **CU-9**: Como usuario que selecciona un modelo en la interfaz, quiero que el servidor procese la validación y el guardado utilizando exactamente el modelo que seleccioné, manteniendo coherencia absoluta entre el modelo en uso y las frases mostradas en el catálogo sin discrepancias.
- **CU-10**: Como usuario del catálogo, quiero ver en cada tarjeta de frase un badge visual que identifique claramente con qué modelo y dimensión fue generada (ej. `BGE-M3 · 1024d` o `MiniLM · 384d`).
- **CU-11**: Como usuario que valida frases, quiero que las tarjetas de retroalimentación de validación y duplicados muestren el badge del modelo utilizado y el umbral de similitud aplicado.

## Criterios de aceptación
- [ ] **CA-01 (Selección dinámica de proveedor en arranque)**: Al iniciar el backend, si `EMBEDDING_PROVIDER=cloudflare`, el sistema debe operar con el proveedor de Cloudflare Workers AI como predeterminado. Si `EMBEDDING_PROVIDER=huggingface`, debe operar con el proveedor de Hugging Face. Si la variable no está definida, debe mantener el comportamiento histórico por defecto (`huggingface`).
- [ ] **CA-02 (Validación estricta de variables de entorno)**: Cuando `EMBEDDING_PROVIDER=cloudflare`, la configuración de entorno debe exigir obligatoriamente `CLOUDFLARE_ACCOUNT_ID` y `CLOUDFLARE_API_TOKEN` con al menos 1 caracter no vacío, y asignar `@cf/baai/bge-m3` como valor por defecto de `CLOUDFLARE_MODEL` si no se especifica. Si faltan credenciales requeridas para el proveedor activo, el servidor debe abortar inmediatamente el arranque con un error de validación descriptivo.
- [ ] **CA-03 (Generación de embedding BGE-M3 de 1024 dimensiones)**: Dado un texto válido normalizado de hasta 280 caracteres, cuando se genera el embedding con Cloudflare Workers AI, se envía una petición HTTP `POST` autenticada con Bearer Token al endpoint de inferencia de Workers AI para el modelo `@cf/baai/bge-m3`, retornando un vector plano de exactamente 1024 números de coma flotante sin valores `NaN` ni nulos.
- [ ] **CA-04 (Manejo tolerante del formato de respuesta de Cloudflare)**: El proveedor debe deserializar correctamente la respuesta de Workers AI tanto si el vector viene en un array unidimensional plano (`result.data: number[]`) como si se devuelve en formato de matriz bidimensional (`result.data: [[number, ...]]`), garantizando siempre la entrega de un array unidimensional de 1024 elementos.
- [ ] **CA-05 (Generalización de similitud coseno a dimensiones dinámicas)**: La función de cálculo de similitud coseno debe aceptar cualquier par de vectores siempre que ambos posean la misma dimensión y dicha dimensión sea mayor que cero. Si las dimensiones difieren, debe arrojar un error de dimensión inválida. Si ambos vectores son de 1024 dimensiones e idénticos, debe retornar `1.0000`; si son ortogonales o de norma cero, debe retornar `0.0000`.
- [ ] **CA-06 (Columna discriminadora de modelo en base de datos)**: La tabla de frases en PostgreSQL debe incorporar la columna `embedding_model` no nula. Las frases preexistentes en la base de datos deben poblarse por defecto con el modelo histórico `'sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2'`. Se debe crear un índice compuesto descendente por modelo y fecha de creación.
- [ ] **CA-07 (Aislamiento estricto de catálogo y comparaciones por modelo)**:
  - Al validar (`POST /api/phrases/validate`) o guardar (`POST /api/phrases`), el servicio acepta un parámetro opcional `model`. Si se especifica, utiliza el proveedor correspondiente a ese modelo y compara exclusivamente contra frases persistidas con dicho modelo. Si se omite, utiliza el modelo predeterminado del servidor.
  - Al consultar el catálogo (`GET /api/phrases`), el endpoint filtra por el modelo solicitado o por defecto por el modelo predeterminado del servidor, garantizando coherencia total entre las frases visualizadas y las evaluadas en validación semántica.
- [ ] **CA-08 (Inexistencia de Fallback automático entre proveedores)**: Si la llamada a Cloudflare Workers AI falla o agota la cuota (HTTP 429), el sistema **NO** debe realizar fallback a Hugging Face. Debe retornar un código HTTP 503 claro y trazable, previniendo costos imprevistos en cuentas pagadas y contaminación entre modelos.
- [ ] **CA-09 (Reintentos y resiliencia ante errores de red y HTTP 429/503)**: Si Cloudflare devuelve respuestas HTTP 429 (límite de cuota) o HTTP 500/503 (indisponibilidad temporal), el proveedor debe ejecutar hasta 2 reintentos con retraso progresivo antes de declarar la indisponibilidad definitiva del servicio.
- [ ] **CA-10 (Diagnóstico CLI y calibración de umbral)**: El comando `npm run test:cf` ejecuta un diagnóstico interactivo con las credenciales de entorno, imprimiendo: latencia en ms, forma del tensor (1024), scores frente a 3 frases canónicas (idéntica $\ge 0.99$, paráfrasis $\ge 0.75$, no relacionada $\le 0.40$) y emite una recomendación del umbral óptimo para BGE-M3.
- [ ] **CA-11 (Aislamiento de pruebas automatizadas)**: La suite de tests automatizados debe ejecutar sin credenciales reales de Cloudflare mediante un proveedor simulado a 1024 dimensiones con identificador `@cf/baai/bge-m3`, alcanzando 100% de éxito sin peticiones HTTP externas.
- [ ] **CA-12 (Endpoint informativo de configuración del modelo activo GET /api/model)**: El backend expone la ruta `GET /api/model`, respondiendo con HTTP 200 y JSON `{ success: true, data: { provider: string, modelIdentifier: string, dimension: number, threshold: number } }`. Este endpoint debe responder inmediatamente en memoria sin consultar la base de datos ni servicios externos de IA.
- [ ] **CA-13 (Filtrado opcional por modelo en catálogo GET /api/phrases?model=...)**: El endpoint `GET /api/phrases` admite el parámetro query opcional `model`. Si se especifica, filtra las frases coincidentes con dicho modelo. Si se omite, mantiene como valor por defecto el modelo predeterminado del servidor.
- [ ] **CA-14 (Header dinámico con selector de modelos y badge de umbral)**: La cabecera de la aplicación carga en montaje la configuración del modelo activo vía `GET /api/model`. Presenta un selector con los 2 modelos soportados (`@cf/baai/bge-m3` y `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`). Al lado del modelo activo en el backend se muestra un indicador visual ("Activo en servidor"). El badge de umbral muestra dinámicamente el porcentaje real recibido del servidor.
- [ ] **CA-15 (Selección dinámica y unificada de modelo en frontend)**: Al cambiar la opción en el selector de modelos, la aplicación conmuta dinámicamente el modelo activo para toda la sesión de usuario: las solicitudes de validación semántica (`POST /api/phrases/validate`) y de guardado (`POST /api/phrases`) envían dicho modelo al backend, y el catálogo de frases recarga automáticamente sus datos consultando `GET /api/phrases?model=:selectedModel`.
- [ ] **CA-16 (Badge de modelo y dimensiones en tarjetas del catálogo)**: Cada elemento del catálogo muestra un badge visual con el nombre corto del modelo y la dimensionalidad del embedding (ej. `BGE-M3 · 1024d` o `MiniLM · 384d`), permitiendo identificar con claridad la procedencia técnica del vector persistido.
- [ ] **CA-17 (Retroalimentación del modelo activo en validación y duplicados)**: Las tarjetas de retroalimentación de validación y duplicado incluyen un indicador visual que detalla el modelo con el que se realizó la inferencia (ej. `BGE-M3 · 1024d`) y el umbral de corte utilizado para declarar el resultado.
- [ ] **CA-18 (Validación estricta de modelos permitidos en el backend)**: En todas las operaciones de la API (`POST /api/phrases/validate`, `POST /api/phrases` y `GET /api/phrases`), el backend valida que cualquier modelo suministrado pertenezca estrictamente al conjunto de los 2 modelos autorizados (`@cf/baai/bge-m3` y `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`), rechazando cualquier otro modelo con un error de validación HTTP 400.

## Requisitos funcionales
- **RF-1 (Contrato de Proveedor de Embeddings con Identificador de Modelo)**:
  - La abstracción del proveedor de inferencia expone la operación de generación de embeddings retornando un array numérico y una propiedad de solo lectura con el identificador del modelo (ej. `'@cf/baai/bge-m3'` o `'sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2'`).
  - Aplica normalización de entrada (recorte de extremos y colapso de espacios múltiples) y rechaza texto vacío arrojando un error de validación temprana sin generar llamadas externas.
- **RF-2 (Cliente de Inferencia para Cloudflare Workers AI)**:
  - Cliente de inferencia que consume el endpoint REST de Cloudflare Workers AI utilizando autenticación por Bearer Token y payload estructurado con el texto normalizado.
  - Desempaquetado tolerante: extracción de vector plano de 1024 floats a partir de respuestas unidimensionales o matrices bidimensionales.
  - En caso de error HTTP externo, extracción del mensaje de error del proveedor y encapsulamiento en un error de servicio externo sin exponer credenciales ni identificadores privados de cuenta.
- **RF-3 (Gestión y Validación de Variables de Entorno)**:
  - Soporte de configuración de entorno para selección de proveedor (`cloudflare` o `huggingface`), credenciales de Cloudflare (Account ID, API Token), modelo y Gateway opcional.
  - Validación condicional cruzada: si se selecciona Cloudflare, se exigen credenciales de Cloudflare; si se selecciona Hugging Face, se exige el token correspondiente.
- **RF-4 (Cálculo de Similitud Coseno con Dimensionalidad Dinámica)**:
  - Motor de similitud matemática desacoplado de dimensiones fijas: valida concordancia dimensional entre ambos vectores ($N_A = N_B > 0$) y ejecuta el cálculo con normalización, acotamiento numérico en $[0.0, 1.0]$ y redondeo a 4 decimales.
- **RF-5 (Aislamiento en Base de Datos y Repositorio por Modelo)**:
  - Incorporación de columna discriminadora de modelo en la entidad de frases y creación de índice compuesto para consultas paginadas ordenadas por fecha y modelo.
  - Las consultas de catálogo y de vectores para cálculo de similitud se filtran estrictamente por el modelo solicitado o activo.
  - Las nuevas frases se almacenan asociadas al identificador del modelo con el que se generó su vector.
- **RF-6 (Herramienta de Diagnóstico CLI y Calibración)**:
  - Script ejecutable mediante comando de desarrollo para verificar la conectividad con Cloudflare Workers AI, medir latencia, validar dimensiones del tensor y evaluar scores frente a frases de prueba, emitiendo una recomendación de calibración para el umbral de similitud.
- **RF-7 (Endpoint de Consulta de Modelo Activo `GET /api/model`)**:
  - Endpoint HTTP de lectura ligera que responde con la configuración predeterminada del servidor (`provider`, `modelIdentifier`, `dimension`, `threshold`) en memoria, sin consultar base de datos ni consumir APIs de IA externas.
- **RF-8 (Selección y Validación de Modelo en Operaciones de API)**:
  - Los endpoints de validación, creación y consulta de catálogo admiten el parámetro de modelo para permitir operar dinámicamente con cualquiera de los modelos autorizados.
  - Se valida estrictamente que el modelo pertenezca a la lista de los 2 modelos permitidos, devolviendo HTTP 400 ante identificadores no admitidos.
- **RF-9 (Catálogo de Modelos Soportados y Metadatos en Frontend)**:
  - Definición constante en la interfaz de los 2 modelos soportados (identificador, etiqueta completa, etiqueta abreviada, proveedor y dimensiones).
  - Tipado estricto en la capa cliente para la información del modelo activo y el identificador de modelo en los elementos del catálogo.
- **RF-10 (Integración en Interfaz de Usuario)**:
  - Encabezado: consulta la configuración del servidor al iniciar, renderiza el selector de los 2 modelos marcando el activo predeterminado en el backend y muestra el porcentaje de umbral real.
  - Validación y Guardado: envía el modelo seleccionado en el encabezado a los endpoints de validación y creación de frases.
  - Catálogo: actualiza el listado según el modelo seleccionado en el encabezado.
  - Tarjetas de frases: muestran un badge visual distintivo con la etiqueta corta del modelo y sus dimensiones.
  - Tarjetas de validación y duplicados: indican el modelo utilizado en la inferencia y el umbral de corte evaluado.

## Requisitos no funcionales
- **RNF-1 (Rendimiento del Cálculo Vectorial)**: El cómputo de similitud coseno sobre vectores de 1024 dimensiones debe ejecutarse en menos de 0.2 milisegundos por par en CPU backend estándar.
- **RNF-2 (Seguridad Estricta de Credenciales)**: Tokens de API e identificadores de cuenta se configuran exclusivamente en variables de entorno. Prohibido exponerlos en logs, respuestas JSON, clientes web o suites de tests (`specs/constitution.md` Sección 3.1).
- **RNF-3 (Cero Tipos `any` y Modo Estricto)**: Compilación TypeScript 100% limpia bajo `"strict": true` sin uso de `any` (`specs/constitution.md` Sección 4.3).
- **RNF-4 (Aprovechamiento de Capa Gratuita y Caché LRU)**: Los vectores de 1024 dimensiones se indexan en caché en memoria con clave compuesta por modelo y texto normalizado, evitando llamadas redundantes a la API externa y protegiendo la cuota gratuita diaria.
- **RNF-5 (Aislamiento de Tests y Cero Dependencias de Red)**: Toda la suite de pruebas automatizadas debe ejecutarse con proveedores simulados, predecibles, deterministas y completándose en pocos segundos sin salida a red externa.
- **RNF-6 (Integridad de la Constitución y Stack)**: Actualización de la documentación técnica y de gobernanza para reflejar el soporte multi-proveedor y la discriminación por modelo.
- **RNF-7 (Accesibilidad y Fluidez en Interfaz de Usuario)**: El selector de modelos debe disponer de accesibilidad completa por teclado (etiqueta descriptiva, contraste WCAG AA), y los cambios de filtro no deben provocar parpadeos ni recargas completas del navegador.
- **RNF-8 (Cero Regresiones en Suites Automatizadas)**: Todas las pruebas unitarias y de integración del frontend y del backend deben superar el 100% de éxito.

## Casos extremos
- **CE-1 (Coexistencia de frases de diferentes modelos en la base de datos)**: Si la base de datos contiene frases previas creadas con Hugging Face y se activa Cloudflare, el sistema no colisiona ni mezcla vectores. Cada frase queda etiquetada con su modelo y las operaciones de similitud operan exclusivamente sobre el espacio vectorial correspondiente.
- **CE-2 (Prohibición estricta de Fallback silencioso entre modelos)**: Si Cloudflare devuelve HTTP 429 por agotamiento de cuota diaria o caída temporal, el sistema no recurre de forma encubierta a Hugging Face. El fallo se transforma limpiamente en HTTP 503, protegiendo al usuario de cargos no autorizados en su cuenta pagada y evitando la corrupción del catálogo con vectores dispares.
- **CE-3 (Agotamiento del límite de cuota o rate limit de Cloudflare - HTTP 429)**: Reintentos con backoff progresivo antes de declarar indisponibilidad estructurada.
- **CE-4 (Credenciales de Cloudflare inválidas o Account ID inexistente - HTTP 401 / 404)**: Detección temprana que aborta sin reintentos innecesarios, arrojando un error tipado claro.
- **CE-5 (Texto de entrada vacío o de puros espacios en blanco)**: Detección síncrona en la capa de normalización que rechaza la entrada previo a cualquier llamada de red.
- **CE-6 (Latencia excesiva o timeout de red con Cloudflare)**: Cancelación automática con control de timeout tras 8000 ms, reintento controlado y retorno de HTTP 503 en caso de fallo persistente.
- **CE-7 (Vector de magnitud cero en 1024 dimensiones)**: Manejo defensivo en similitud coseno retornando `0.0000` si la norma euclidiana es cero, neutralizando divisiones por cero.
- **CE-8 (Dimensionalidad inesperada desde Workers AI)**: Si la API externa responde con un número de dimensiones distinto de 1024, el proveedor aborta con error de formato antes de permitir la persistencia del vector.
- **CE-9 (Indisponibilidad o fallo al consultar `GET /api/model`)**: Si el endpoint de modelo no responde o devuelve error de red, la interfaz cliente recurre defensivamente a valores por defecto estándar sin bloquear la UI ni provocar pantalla en blanco.
- **CE-10 (Catálogo vacío para el modelo seleccionado en el filtro)**: Si el usuario selecciona un modelo para el cual aún no existen frases en la base de datos, el catálogo muestra un mensaje amigable indicando que no hay frases registradas bajo ese modelo.
- **CE-11 (Frases históricas con modelo desconocido o anómalo)**: Si una frase en la base de datos tuviese un identificador de modelo no contemplado en la lista de modelos de la interfaz, la tarjeta renderiza un badge genérico seguro mostrando el identificador de forma amigable sin lanzar excepciones de renderizado.
- **CE-12 (Petición con modelo no autorizado o malicioso)**: Si un cliente envía un identificador de modelo ajeno a los 2 soportados en validación, guardado o consulta, el backend lo rechaza inmediatamente con HTTP 400 Bad Request.
